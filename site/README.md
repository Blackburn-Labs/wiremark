# wiremark docs site

The [Docusaurus](https://docusaurus.io/) site that publishes the guides and
component reference in [`../docs`](../docs) to **docs.wiremark.dev**. The main
marketing site (`www.wiremark.dev`) is a separate repo; this builds only the
docs.

## How it works

- The site reads [`../docs`](../docs) **in place** (`docs.path: '../docs'` in
  `docusaurus.config.js`). The Markdown is never copied — edit it in `../docs`
  and it shows up here.
- `prestart`/`prebuild` run `node ../scripts/generate-reference.mjs`, which
  regenerates [`../docs/reference/components.md`](../docs/reference/components.md)
  from [`../meta/mui-support-matrix.json`](../meta/mui-support-matrix.json) (the
  single source of truth) before every dev server start and production build.
- Sidebar category labels live in `sidebars.js`; the items inside them are
  autogenerated from the folder and ordered by the `01-`/`02-` filename
  prefixes, so new guides appear with no config changes. Nothing
  Docusaurus-specific is added to `../docs`.

## Run locally

```sh
cd site
npm install        # first time only (installs Docusaurus into site/node_modules)
npm start          # dev server with live reload at http://localhost:3000
```

Other commands:

```sh
npm run build      # regenerate the reference, then build static site -> site/build
npm run serve      # serve the production build locally
npm run clear      # clear the Docusaurus cache
```

## Deploy (Netlify, continuous)

You do not build or deploy by hand -- Netlify does it on every push. One-time
setup (~5 min):

1. Make sure this repo is pushed to GitHub (it is: `Blackburn-Labs/wiremark`).
2. In Netlify: **Add new site -> Import an existing project -> Deploy with
   GitHub**, authorize, and pick `Blackburn-Labs/wiremark`.
3. Netlify reads the committed [`../netlify.toml`](../netlify.toml) and pre-fills
   everything -- base directory `site`, build command `npm run build`, publish
   directory `site/build`. Click **Deploy site**.
4. Under **Domain management**, add the custom domain `docs.wiremark.dev` and
   point DNS as Netlify instructs.

From then on it is automatic:

- Every push to `main` -> production rebuild + deploy.
- Every pull request -> its own **deploy preview** URL.
- Each build runs `npm ci` (from the committed `package-lock.json`), then
  `npm run build`, whose `prebuild` regenerates the reference from the JSON
  before Docusaurus builds. You never run a production build locally.

Paths in `netlify.toml` are relative to `base = "site"`, so `publish = "build"`
resolves to `site/build`. For a one-off manual deploy you can run
`npx netlify deploy --prod`, but with the Git integration you will not need it.

### Serving under www.wiremark.dev/docs instead

The build is base-path-ready. To serve the docs under the main domain without
merging repos, set these env vars on the Netlify docs site:

```
DOCS_URL      = https://www.wiremark.dev
DOCS_BASE_URL = /docs/
```

then add a proxy rewrite on the **main** site (its `_redirects`):

```
/docs/*  https://<this-docs-site>.netlify.app/docs/:splat  200
```

## Notes / conventions

- **This is a standalone package, not a hoisted npm workspace** (it is not in the
  root `package.json` `workspaces`). That keeps `npm install` for the core
  library light instead of pulling Docusaurus's dependency tree. To make it a
  formal workspace later, add `"site"` to the root `workspaces` array.
- `.md` is parsed as **CommonMark** (`markdown.format: 'md'`), not MDX, so the
  generated HTML-comment banner and any literal `<` / `{` render fine.
- The footer shows `Copyright (c) 2026 Blackburn Labs` on every page
  (`themeConfig.footer.copyright`).
- A few links in the docs point at repo files (e.g. the source JSON) that are
  not published here, so `onBrokenLinks` is set to `warn`. Convert them to
  absolute GitHub URLs once the repo URL is settled to make them resolve on the
  site too.
